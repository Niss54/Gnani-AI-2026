# Repository audit and local remediation

This audit does **not** establish completion of the master PRD or production readiness. The previous status file overstated completion. Local code, actual trained weights, measured model quality, recorded speech quality and a production rollout are separate deliverables.

Audit baseline: `8bf88d9`. No commit, push, deployment, outbound call, email, payment, paid compute purchase or remote migration was performed by this audit. Existing commits were already present when this audit resumed.

## Resume instructions

1. Configure the variables in `local.env.example` privately. Never send keys in chat. `VOICE_USER_TENANTS` must map verified Supabase user IDs to the actual authoritative tenant; no browser-provided tenant is trusted. Internal carrier callbacks currently require one explicitly configured internal tenant. Multi-tenant carrier resolution still needs a trusted call mapping.
2. Start the isolated voice app with `.venv-voice-win\Scripts\python.exe -m uvicorn backend.voice_app:app --host 127.0.0.1 --port 8000 --env-file <private-env-file>`. This avoids importing the legacy provider singletons in `backend/main.py`.
3. Integrate the real invoice/contact/mandate source into the voice repository. Do not copy dashboard demo defaults into it. Implement authorized phone targeting, payment mapping, provider receipts and durable outbox/reconciliation before re-enabling blocked routes.
4. Have bilingual reviewers correct the draft dialogues and sign content-hash-bound review receipts. Review semantic distinctness, not just count. Run `npm run verify:dataset`; it must pass both human and complete-corpus checks.
5. Provision an explicitly authorized CUDA environment, install `training/requirements.txt`, resolve a tested lock, cache the exact base model/tokenizer revisions, then run smoke and full training. The requirements file is a candidate dependency range, not a verified GPU lock. No cloud compute was purchased here.
6. Implement and run actual candidate/base/hosted inference against development data; freeze verified artifacts before locked-test access. Packaging currently refuses promotion because clean-process reload and qualification are absent. Do not replace these blockers with static passing values.
7. Run recorded Hinglish and English scenarios with authorized test recipients. Measure missed objections, interruptions, repeat requests, latency, amounts/dates, intelligibility and human-rated naturalness. Tune voice/provider choices from these recordings.
8. Finish deployment, tenant isolation for dashboard/legacy data, monitoring, recovery drills and the reviewed pilot. Release verification must remain nonzero until the PRD acceptance evidence exists.
